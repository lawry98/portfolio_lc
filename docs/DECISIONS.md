## D-13 · T6 retype-reward half: pure span-engine, `ATE`→`retyping` reroute, live-caret DOM contract — 2026-08-24
**Choices:** (1) **The retype schedule is a PURE decision-core** (`createRetype`/`buildRetypeSchedule` in `retype.ts` — imports neither gsap nor three, no wall-clock, no `Math.random`; jitter/cadence come only from an injected `random: () => number`, default `() => 0.5`), unit-tested by `retype.test.ts` (24 tests), mirroring the SPEC §4.3 decide/execute split and the `fsm.ts`/`glyphs.ts` precedent. `renderRetype` (same file, DOM-only) applies a frame to per-char `.byte-char` spans + moves an absolutely-positioned caret via `transform`. This realizes **D-03** (a custom span engine, NOT SplitText — SplitText stays only for the manifesto/hero masked reveals). (2) **`retyping` is made reachable by rerouting `eating --ATE--> retyping`** (was `→idle`) + a new retype-driver-fired **`RETYPED`** event (`retyping→idle`) + a generous `retypeMs`(4000) safety cap — the exact REACHED/ATE mirror (engine sends the beat, the pure FSM accepts it). The linear `dashing→eating→retyping→idle` chain serializes each feed's eat→retype→queue-drain (the feeder drains on `onEnter('idle')`), avoiding a race with an off-`onEat` trigger; the `eating` safety cap still exits to `idle` (emergency path skips the reward — deliberate asymmetry). (3) **`createBytePet` owns the retype DOM but stays page-agnostic:** it tags the two headline line elements with its OWN `data-byte-line="0|1"` attributes and creates a `data-byte-caret` caret (never a page CSS class), so `renderRetype` resolves them by attribute — robust to the hero's SplitText wrapping. (4) **The caret is resolved LIVE at every use** (`headlineEl.querySelector('[data-byte-caret]')`, re-appending a seed if absent) and positioned via `getBoundingClientRect` deltas relative to `#hero-headline` — because the hero load-reveal SplitText's revert restores CLONED headline children, which would otherwise orphan a captured node reference (caught in browser QA; `offsetParent`-relative offsets were likewise fragile). (5) **Reduced motion** → an instant text set via `enqueue; step(0); step(MAX)` (a lone `step(MAX)` anchors the engine clock and renders the STALE phrase — R-T6a-9) with no Byte glide/spark; the caret's CSS blink stays (SPEC §12). (6) **Phrase cycling** is wired via a new additive `PetOptions.phrases` (`main.ts` passes `phrases.identity`); the lab phrase-set axis (Identity/Punchy/combined) remains T8. **No new runtime deps** — gsap/three were already in.
**Why:** the pure-core/executor split keeps the retype decision logic unit-tested + framework-agnostic while GSAP animates Byte and the DOM; the event-driven `retyping` keeps the FSM a pure function of config+events+ms even as per-char timing varies; the attribute-based, live-resolved caret makes the retype robust to SplitText's DOM churn without coupling `pet/` to page markup. **Entrance-half note:** `hidden`/`entering` become reachable via the SAME engine-beat pattern, the entrance's live-type reuses `createRetype`/`renderRetype` from an empty start, and the audible "soft tick every 2–3 chars" (`typeTick`) is deferred to T7 (no `SoundEngine` until then). This half did NOT flip TICKETS T6→DONE (entrance pending), did NOT merge, and kept the `.superpowers/sdd/t6a-plan/` audit trail.

## D-12 · T5 feeding loop: pure glyph-queue core, event-driven `eating` (REACHED/ATE), sleep-allowlist fix, footer counter — 2026-08-23
**Choices:** (1) **The glyph queue/counter is a PURE decision-core** (`createGlyphQueue` in `glyphs.ts` — no gsap/three) that `createFeeder` (`feed.ts`) executes with GSAP/three, mirroring the SPEC §4.3 decide/execute split and the FSM precedent; `glyphs.test.ts` unit-tests it (cap 3 pops the oldest non-eating entry, `onEat` increments the running total) plus `makeGlyph` (6 bevel-extruded `THREE.Shape` kinds `{ ; > * + =`, no `typeface.json`) — the ticket's tested core, needing no `WebGLRenderer`. (2) **`eating` is made reachable via explicit feeder-fired FSM events `REACHED` (dashing→eating) and `ATE` (eating→idle)**, NOT by matching a fixed FSM timer to a GSAP duration (the dash is 380–600ms *by distance*); the durations live in the animation layer and the FSM stays pure/deterministic. Generous safety caps (`dashMs`→1200, new `eatMs`=1500) exit to `idle` only if a beat is ever dropped, so the FSM can't wedge. (3) **MUST-FIX (carry-forward #1): `isSleepEligible` denylist → explicit awake-resting-state allowlist `{idle, curious, invited, peeking}`**, landed in the SAME change that makes `eating` reachable — it excludes `dashing`/`eating` (Byte finishes feeding before the 30s-idle overlay) and the unreachable/active `hidden`/`entering`/`retyping`/`traveling`, and keeps `peeking` (peeks deliberately don't reset the sleep accumulator, so a late peek must still be able to sleep out). (4) **The feeder drives dashing/eating choreography via `fsm.onEnter`** (enter dashing → dash to the front-of-queue glyph → `REACHED`; enter eating → chomp into `mouthWorld()` + particles + count + dispose → `ATE`; enter idle → drain the queue via a legal `FEED`), so one path covers both the idle/curious/invited→`FEED`→dashing route and the sleeping→`POINTER_DOWN`→waking→dashing "wake counts as a feed" payoff; `createBytePet.dispatch()` therefore no longer plays `Dash`/`Eat` (no double-drive) and gained a **stale-transition guard** (`if (fsm.state() !== state) return;`) after a nested re-entrant transition (the feeder re-chaining idle→`FEED`→dashing synchronously inside `enter('idle')`) was found replaying `Idle` over the fresh Dash and fighting the bank. (5) **Root-placement handoff:** `onTick` hard-pins Byte to the headline anchor only in home states; the feeder owns `rig.object3d.position` during dashing/eating; a no-snap "reacquire" glide returns Byte to the anchor on the first home tick; the blob-shadow follows the actual root position, not the recomputed anchor (its `MAX_HOVER_HEIGHT=64` vertical tuning is unchanged — the dash is horizontal locomotion, only the tossed glyph arcs vertically). (6) **The FED counter lives in the FOOTER** (`[data-fed-counter]`, SPEC §8.6 — TICKETS' "hero.ts" file-hint was stale; the element shipped in the footer at T2); `createBytePet` surfaces the running total via `BytePetHandle.onEat`, and `main.ts` renders `FED N GLYPHS`, keeping `pet/` free of page copy. (7) **`createFeeder`'s signature is extended** with an additive `deps` bag `{ prefersReducedMotion: () => boolean; unitPx: number }` (reduced-motion honored per-feed via a live accessor reading `createBytePet`'s `reducedActive`; glyphs sized to the headline scale). **No new runtime deps** — `THREE.Shape`/`ExtrudeGeometry`/`Points` and GSAP were already in the bundle.
**Why:** the pure-core/executor split keeps the feeding decision logic unit-tested and framework-agnostic while GSAP/three animate; event-driven `eating` keeps the FSM a pure function of config + events + ticked ms even as tween durations vary by distance and motion preference; the allowlist fix is the carried-forward correctness requirement (no sleeping mid-eat) applied exactly when `eating` becomes reachable; the onEnter-driven feeder plus the stale-transition guard make the choreography robust to the synchronous re-entrancy the queue-drain introduces; the root-placement handoff resolves the dash-locomotion-vs-anchor-pin conflict without a visible snap; and the footer counter honors SPEC §8.6 while keeping the module portable. **T-GLB note:** the real GLB rig must still expose `mouthWorld()` (glyphs converge there) and in-place `Dash`/`Eat` clips (the feeder owns locomotion + the glyph tween).

## D-11 · T4 rig-owned Body/Glow theming + scene layer helpers + pure config-injected FSM — 2026-08-23
**Choices:** (1) **Byte owns its material theming via the `PetRig`** (`setBodyColor`/`setGlow`); `scene.setTheme` now re-lerps **lights only** — the T3 blanket "repaint every `MeshStandardMaterial`" was removed (its sole consumer was the deleted `?glcube` cube). On a theme change `createBytePet` calls `scene.setTheme(t)` + `rig.setBodyColor(bodyColorForTheme(t))` + `rig.setGlow(t==='dark', DEFAULT_GLOW_ACCENT)` (mint `#38e8a8`; the lab glow axis lands at T8). **T-GLB's real rig must own `Body`/`Glow` the same way** (glow ≠ body recolor — SPEC §11 phosphor accent). (2) **`scene.addToPet(obj)` / `addToFront(obj)`** helpers retire the T3 layer footgun (three.js render layers don't cascade from a parent `Group`): `addToPet` re-applies the current behind/front layer to the object + descendants; `addToFront` sets `FRONT_RENDER_LAYER` on them. **T5's glyphs/particles use `addToFront`.** (3) **The FSM (`fsm.ts`) is pure + deterministic + config-injected** — imports neither gsap nor three, no wall-clock/`Math.random`; time enters only via `tickTimers(dtMs)` (milliseconds). All randomness + micro-behaviour scheduling live in `createBytePet`, not the FSM. `tickTimers` performs at most one transition per call, evaluating the current state's own timed exit **before** the generic idle→sleeping overlay (a peek/curious completes before Byte sleeps). (4) **`createBytePet` owns the scene** (SPEC §4.4) — it calls `createScene`/`startTicker` internally; `main.ts` only holds the returned `BytePetHandle`. **No new runtime deps:** `RoundedBoxGeometry` ships inside the installed `three@0.185.1` (`three/addons/geometries/RoundedBoxGeometry.js`).
**Why:** the blanket material repaint would clobber the emissive glow with the body color; rig-ownership keeps glow independent and mirrors the placeholder→GLB swap contract. The layer helpers prevent a recurring invisible-mesh bug as T5+ add `frontLayer`/`petLayer` call sites. FSM purity keeps the decision core unit-tested (39 tests) and framework-agnostic while GSAP/`AnimationMixer` execute. Scene ownership matches the locked module API.

## D-10 · T3 runtime dep: three@^0.185.1 (+ @types/three devDep) — 2026-08-22
**Choice:** Added `three@^0.185.1` under `dependencies` — the last big locked-stack dependency (SPEC §14). Installed `three` doesn't bundle its own `.d.ts` files (checked `node_modules/three/package.json`: no `types`/`typings` field, and zero `*.d.ts` files under `node_modules/three`), so `@types/three@^0.185.4` was added under `devDependencies` so `tsc` can resolve `three`/`three/addons/*` types. Confirmed via context7 (`/mrdoob/three.js`) that the addon import paths for this version are `three/addons/loaders/GLTFLoader.js` and `three/addons/loaders/DRACOLoader.js` (both resolve under `examples/jsm/loaders/` per the package's `exports` map, `"./addons/*": "./examples/jsm/*"`) — recorded now for Task 4/T-GLB, not used in this task. DRACO decoder path is `/draco/` (`DRACOLoader.setDecoderPath('/draco/')`, decoder files served from `public/draco/`); no decoder files ship yet — nothing decodes before T-GLB. `RoundedBoxGeometry` (placeholder body) is deferred to T4.
**Why:** three earns its keep starting T3 (WebGL occlusion sandwich); locking the version now lets DECISIONS and the Task 4 addon-loader work point at the same release. Bundle math: three ≈ 165KB gz is the bulk of the 280KB JS ceiling (SPEC §14) and T2 measured 54.8KB gz, so there's headroom even before code-splitting or tree-shaking; the actual post-three number is measured and logged in Task 5 QA, not guessed here.
